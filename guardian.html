Building My Own SSH IP Blocker for Linux

Hey there! Long time no see. Today I built an SSH IP blocker for Linux from scratch. I've been diving deeper into Linux lately, and honestly, what's more fun than learning by building something yourself?

Why Reinvent the Wheel?

Great question! Tools like Fail2Ban already do this—and they do it well. But my goal isn't just to block IPs; it's to understand how and why these tools work under the hood. The Linux world is vast, like an endless rabbit hole, and I'm trying to wrap my head around it, one script at a time.

What Does My Script Actually Do?

In simple terms, GuardianSSH (that's what I named it) does three things:

  • Watches your SSH logs for failed login attempts
  • Tracks suspicious IPs across multiple scans
  • Blocks malicious IPs automatically using your system firewall

It's written in Python, uses only the standard library, and works on Ubuntu, Arch, and Fedora. No external dependencies—just pure logic.

The Challenge: Make it universal

I develop on Arch Linux, which doesn't use /var/log/auth.log like Ubuntu does. Instead, it uses journalctl for logging. Oh, and it doesn't come with ufw by default.

Solution? I added firewall auto-detection. Now the script checks for ufw, firewalld, or iptables and uses whichever is available. Cross-distribution compatibility (I guess)

A Quick Code Sneak Peek

Here's the core regex that finds malicious IPs in the logs:

pattern = re.compile(r"Failed password for .* from (\d+\.\d+\.\d+\.\d+)")

Simple, right? But pairing this with state persistence (saving counts to a JSON file) is what makes the script smart enough to catch slow, distributed attacks.

What I Learned

  • Never assume your environment - always code for portability
  • Localhost protection is non-negotiable (don't block 127.0.0.1!)
  • Reading system logs is different on every distro
  • Security tools need safety rails, not just features
